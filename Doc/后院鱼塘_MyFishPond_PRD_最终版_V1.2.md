# 1. 产品概述

## 1.1 产品定位

“后院鱼塘 MyFishPond”是一款面向 Windows 桌面的轻量互动动态桌面应用，以俯视池塘为核心场景，通过实时渲染展示清澈水体、锦鲤、小型观赏鱼、荷叶、荷花、水草、石块、水面波纹及轻量光影等元素。

产品不是播放循环视频，而是持续运行的小型实时生态场景。鱼类具有自主游动、平滑转向、局部聚群、避让、受惊等行为，水面和环境元素保持持续但克制的动态反馈，并可通过鼠标产生轻度互动。

产品首期优先保障 Windows 的稳定性、低资源占用和完整体验；核心渲染与业务逻辑保持平台无关，为后续 macOS 版本保留扩展能力。

## 1.2 产品核心价值

1. 在桌面中提供一个安静、自然、长期陪伴的小鱼塘；
2. 相比视频壁纸，鱼群和水面具有实时变化，不容易产生循环感；
3. 相比游戏化养鱼产品，不要求签到、任务、升级，避免打扰用户；
4. 相比重型 3D 动态桌面，以低功耗、低资源占用为核心竞争力；
5. 允许鱼塘主通过简单设置调整鱼群、互动和性能档位。

## 1.3 宣传语

> **把一方鱼塘，养在桌面上。**

# 3. 产品目标

## 3.1 核心目标

1. 构建自然、真实、有生命感的桌面鱼塘；
2. 实现鱼类自然游动、平滑转向、局部鱼群及基础生态行为；
3. 实现鼠标惊鱼、点击波纹等轻量交互；
4. 在 1080P、2K、4K、高 DPI 环境下长期稳定运行；
5. 将 CPU、GPU、内存和功耗控制作为 P0 能力；
6. V1.x 优先完成 Windows 正式版；
7. 核心代码不与 Windows API 强耦合，为后续 macOS 复用；
8. 为后续投喂、昼夜、天气、多主题等能力预留空间。

## 3.2 首版成功标准

- 池塘整体画面自然，无明显视频循环感；
- 鱼类运动不机械、不频繁撞边、不大面积重叠；
- 局部鱼群能自然形成和散开；
- 鼠标靠近时仅附近鱼产生合理反应；
- 点击水面产生自然波纹；
- 标准模式适合全天候桌面驻留；
- 全屏应用或桌面不可见时自动暂停或降载；
- 连续运行 8 小时无明显内存泄漏和资源异常增长。

# 4. 核心产品原则

1. **稳定运行优先于特效数量。**
2. **低功耗优先于高帧率。**
3. **自然感优先于动画复杂度。**
4. **桌面属性优先于游戏属性。**
5. **低干扰优先于强视觉刺激。**
6. **先做好鱼塘，再扩展其他生态内容。**
7. **首期优先做好 Windows，不为未来平台过度增加当前复杂度。**
8. **视觉上看起来丰富，计算上保持简单。**

# 5. 目标平台

## 5.1 首期：Windows

V1.x 以 Windows 10 / Windows 11 为唯一正式开发、调优、验收和发布平台。

要求：

- 支持 Windows 10 / Windows 11；
- 支持 1080P、2K、4K 和 Windows 高 DPI；
- 支持桌面动态壁纸运行；
- 支持全屏暂停；
- 支持桌面遮挡降载；
- 支持多显示器基础适配；
- 支持开机启动；
- 支持设置持久化；
- 支持锁屏、休眠、分辨率变化后的恢复。

## 5.2 后续：macOS

macOS 不纳入 V1.0 的开发和验收范围。

首期仅要求：

- 核心渲染代码不依赖 Windows API；
- 场景、鱼类、鱼群、交互、设置、性能管理保持平台无关；
- Windows 特有能力通过 Adapter / Host 隔离。

后续 macOS 版本原则上复用 PixiJS/WebGL 核心，仅新增 macOS Desktop Host、WKWebView 及系统能力适配。

# 6. 目标用户与使用场景

## 6.1 目标用户

- 喜欢自然、安静桌面风格的 Windows 用户；
- 长时间使用电脑的办公用户；
- 使用 2K、4K、大尺寸或超宽屏显示器的用户；
- 希望动态桌面有生命感，但不希望桌面变成游戏的用户。

## 6.2 核心场景

### 6.2.1 日常桌面

鱼塘主回到桌面后，看到鱼群自然游动，水面保持轻微动态。

### 6.2.2 鼠标经过

鼠标接近鱼群时，附近鱼产生轻微回避或短时受惊加速。

### 6.2.3 点击水面

点击桌面空白水面位置产生局部扩散波纹。

### 6.2.4 长时间办公

应用长期驻留，但资源占用保持克制，不明显影响前台应用。

### 6.2.5 全屏场景

进入游戏、视频、演示等全屏应用后，鱼塘自动暂停或进入极低负载状态。

# 8. 池塘场景需求

## 8.1 池塘背景

采用俯视自然庭院池塘风格。

要求：

- 无明显平铺接缝；
- 不同屏幕比例下合理裁切；
- 左侧常见桌面图标区域保持相对干净；
- 中部保留较多水面留白；
- 装饰细节主要向边缘、角落和局部区域集中；
- 不采用高饱和、强游戏感的视觉风格。

## 8.2 荷叶与荷花

- 荷叶尺寸与角度存在差异；
- 允许少量自然重叠；
- 荷花作为少量视觉焦点；
- 不大面积铺满屏幕；
- 允许非常轻微的浮动和旋转。

## 8.3 水草与石块

- 用于加强水下层次；
- 部分水草可位于鱼的前景，形成遮挡；
- 避免元素密度过高。

## 8.4 水面动态

水面持续保持轻微动态：

- 缓慢；
- 不规律；
- 不产生明显海浪感；
- 不采用高成本实时流体模拟；
- 节能模式可简化或关闭部分效果。

## 8.5 水面光影

采用低透明度、低频率的轻量水光效果。

要求：

- 不闪烁；
- 不干扰桌面图标阅读；
- 可随性能档位自动降级。

# 9. 鱼类生态需求

## 9.1 鱼类外观

V1.0 建议提供 4～6 种鱼类外观，以锦鲤和小型观赏鱼为主。

## 9.2 个体差异

每条鱼至少具有：

| 参数 | 说明 |
|---|---|
| 鱼种 | 外观类型 |
| 体型 | 小 / 中 / 大 |
| 基础速度 | 日常巡游速度 |
| 最大速度 | 受惊等状态使用 |
| 转向速度 | 决定灵活程度 |
| 聚群倾向 | 决定加入鱼群概率 |
| 活跃度 | 决定状态变化频率 |

## 9.3 自由游动

基础运动节奏：

```text
缓慢游动
→ 小幅转向
→ 保持方向
→ 偶尔加速
→ 恢复常速
→ 再次调整方向
```

禁止：

- 长时间完全直线运动；
- 高频抖动；
- 原地旋转；
- 明显重复固定轨迹。

## 9.4 平滑转向

普通状态下禁止瞬间 90° 或 180° 转向，方向变化应连续完成。

## 9.5 鱼群行为

局部鱼群主要表现：

- 靠近；
- 方向趋同；
- 保持间距；
- 聚集；
- 散开。

常规鱼群规模建议 3～7 条，不长期形成全屏统一鱼群。

## 9.6 鱼间避让

- 减少长时间重叠；
- 保持合理距离；
- 允许短时间自然交叉。

## 9.7 边缘回避

采用软边界机制：

```text
接近屏幕边缘
→ 回转趋势逐步增强
→ 自然改变方向
→ 返回有效区域
```

禁止碰壁后机械反弹。

# 10. 鱼类行为状态

V1.0 至少包含：

## 10.1 闲游

默认状态，低至中速，小幅随机改变方向。

## 10.2 巡游

较稳定方向、中等速度、持续时间较长。

## 10.3 聚群

与附近鱼保持相似方向及合理距离。

## 10.4 受惊

鼠标快速靠近时触发：

- 短时间加速；
- 远离刺激源；
- 可暂时脱离鱼群；
- 数秒后恢复。

## 10.5 觅食

V1.1 引入，用于点击投喂功能。

# 11. 桌面互动

## 11.1 鼠标惊鱼

- 只影响鼠标附近一定范围内的鱼；
- 鼠标速度越快，影响越明显；
- 距离越近，反应越强；
- 刺激消失后逐渐恢复普通状态；
- 不允许全屏所有鱼同时受惊。

## 11.2 点击波纹

- 波纹从点击位置产生；
- 约 1～3 秒逐步扩散和淡出；
- 支持多个同时存在；
- 设置最大同时数量；
- 不采用真实流体模拟。

## 11.3 点击投喂

V1.1 实施。

```text
投放鱼食
→ 附近鱼感知
→ 鱼群靠近
→ 鱼食被吃掉
→ 鱼逐渐散开
```

## 11.4 拖动扰水

V2.0 可选，默认关闭，避免干扰桌面操作。

# 12. 环境氛围

## 12.1 漂浮颗粒

少量、低透明度、低速移动，不形成明显雪花感。

# 14. 性能与资源控制

性能为 P0 级产品能力。

## 14.1 三档性能模式

| 参数 | 节能 | 标准 | 高质量 |
|---|---:|---:|---:|
| FPS | 20 | **30** | 60 |
| Render Scale | 0.75 | **1.0** | 1.0～1.5 |
| 默认鱼数量 | 15 | **24** | 35 |
| 鱼群计算频率 | 8 Hz | **12 Hz** | 20 Hz |
| 粒子 | 少 | 中 | 多 |
| 水面光影 | 简化 | 轻量 | 完整 |
| 高级效果 | 关闭 | 轻量 | 开启 |

**标准模式为默认模式。**

## 14.2 动态降载

```text
桌面可见
→ 当前性能档位正常运行

长时间无明显互动
→ 可适当降低刷新频率

桌面大面积遮挡
→ 5～10 FPS

桌面完全不可见
→ 暂停主渲染

全屏应用
→ 暂停
```

## 14.3 高 DPI / 4K

- Windows 高 DPI 不强制按最高物理像素渲染；
- 优先通过受控 Render Scale 控制 GPU 压力；
- 4K 场景应优先保证流畅和低功耗，而不是强制所有效果满精度。

## 14.4 计算频率分离

建议：

```text
渲染：20 / 30 / 60 Hz
鱼运动：与渲染同步
Boids：8～20 Hz
行为状态：约 5 Hz
环境决策：1～2 Hz
```

# 16. 视觉设计原则

## 16.1 风格

总体方向：**自然、轻写实、安静、精致、克制。**

避免：

- 高饱和卡通风；
- 过度写实导致视觉沉重；
- 游戏技能式特效；
- 高频闪烁；
- 过密装饰；
- 大量 UI 长期覆盖桌面。

## 16.2 桌面可用性

特别要求：

- 左侧桌面图标常用区域相对干净；
- 中部保留较大开阔水面；
- 视觉焦点不要长期停留在图标区域；
- 鱼群可经过图标区，但不长期聚集。

---

# 17. 非功能需求

## 17.1 稳定性

连续运行 8 小时：

- 不崩溃；
- 内存不持续上涨；
- 临时对象不持续累积；
- 渲染上下文异常后可恢复；
- 鱼数量不会异常增长。

## 17.2 恢复能力

支持：

- 分辨率变化；
- 显示器热插拔；
- 休眠恢复；
- 锁屏恢复；
- 前后台切换。

## 17.3 平台可扩展性

V1.0 不要求 macOS 成品，但核心代码不得直接依赖 Windows 专用 API。

# 23. 验收标准

## 23.1 场景

- 无明显拉伸；
- 无明显素材接缝；
- 中央和左侧保持适量留白；
- 不影响桌面图标识别。

## 23.2 鱼类

连续观察 5 分钟：

- 不出现大面积同步行为；
- 不持续直线撞边；
- 不机械反弹；
- 不长期停在边缘；
- 不大面积重叠；
- 鱼群可自然形成与散开。

## 23.3 互动

- 鼠标只影响附近鱼；
- 回避方向合理；
- 点击波纹位置准确；
- 连续点击不明显卡顿。

## 23.4 性能

至少测试：

- 1080P；
- 2K；
- 4K；
- Windows 高 DPI。

标准模式下：

- 目标 30 FPS；
- 24 条鱼稳定；
- 全屏应用可暂停；
- 长时间运行不持续泄漏内存；
- 不明显影响常规前台办公应用。

## 23.5 平台扩展性

- 核心场景和鱼类逻辑不调用 Windows 专用 API；
- Windows 能力通过 Adapter / Host 实现；
- 后续 macOS 不需要重写核心鱼塘逻辑。

# 24. 技术方案边界

PRD 仅规定：

- PixiJS + WebGL2 为正式渲染路线；
- HTML 仅作为渲染宿主，不采用纯 Canvas 2D 作为正式方案；
- Windows 首发；
- macOS 后续扩展；
- 默认标准模式 30 FPS；
- 动态降载为强制能力；
- 不采用高成本真实流体模拟。

详细工程结构、渲染管线、鱼群算法、Shader、Windows Host、性能策略和后续 macOS Adapter 在独立技术方案中定义。
